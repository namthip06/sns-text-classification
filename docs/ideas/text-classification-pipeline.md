# Text Classification 18 หมวด — Pipeline พร้อมการใช้ Weak Label อย่างปลอดภัย

## Problem Statement

เราจะทำให้ขั้น weak label (tag rule) ที่พลาดได้ **ไม่กัดกร่อนคุณภาพของ classifier 18 หมวดสุดท้าย** ได้ยังไง — โดยรู้ว่า "พลาดแค่ไหนถึงอันตราย" แทนที่จะบินปิดตา

## Recommended Direction

**วัด → gate → พิสูจน์** (Measurement-first): ไม่ให้ weak label เป็น "ครู" โดยปริยาย แต่ให้มันเป็น **ผู้ช่วยคัด (routing) + ผู้สมัครเป็น label (gated)** ใช้ชุด label จาก LLM ที่สร้างอยู่แล้วเป็น referee วัด per-tag precision จากนั้นปลดล็อกเฉพาะ tag ที่แม่น ≥85-90% เข้าเป็น label ฝึก และปิดท้ายด้วย A/B test พิสูจน์ด้วยตัวเลขว่า weak label ช่วยหรือถ่วงจริง

หลักสำคัญ: **LLM label ที่จะสร้างอยู่แล้ว คือ ground truth สำหรับวัด tag rule — ไม่ต้องสร้างชุดวัดแยกเพิ่มเลย**

## Flow ฉบับเต็ม

```
┌──────────────────────────── STAGE 1 : Data prep ────────────────────────────┐
│ [100k unlabeled ทวิตไทย]                                                      │
│  • ตัด URL / @mention                                                        │
│  • ไทยโซเชียล: ตัวซ้ำ → [CREP], "555" → [LAUGH]                               │
│  • เก็บ # ไว้ก่อน (ใช้ขั้น 2) แต่เตรียมการตัดตอนเข้าเทรน                        │
└───────────────────────────────┬──────────────────────────────────────────────┘
                                ▼
┌──────────────────────────── STAGE 2 : Weak label (tag rule) ────────────────┐
│  บทบาท: "ผู้ช่วยคัด + ผู้สมัครเป็น label" (ไม่ใช่ครูโดยปริยาย)                  │
│                                                                              │
│  G1 ■ per-tag precision (เทียบกับ LLM sample) ──► tag แม่น ≥85-90% → label ฝึก  │
│      │                                      └─► tag กลาง/พัง → routing-only   │
│      └─► cap สัดส่วน weak label ใน train set (~≤30-40%)                        │
└───────────────────────────────┬──────────────────────────────────────────────┘
                                ▼
┌──────────────────────────── STAGE 3 : LLM label (Claude/GPT) ───────────────┐
│  • สุ่ม ~2-3k แรก → วัด distribution จริง (รู้ว่าคลาสหายากอยู่ตรงไหน)          │
│  • จัดสรรงบตามนั้น: คลาสหายาก → เจาะด้วย tag hint / โพสต์ไม่มี tag / เสียดสี  │
│  • prompt: 18 หมวด + รายละเอียด + few-shot, ตอบ JSON, temp ~0.2             │
│  • ชุดนี้ใช้ซ้ำเป็น "referee" วัด tag rule (ข้อ G1) ได้ด้วย ไม่ได้เพิ่มต้นทุน   │
│                                                                              │
│  G2 ■ ตรวจคุณภาพ LLM label: สุ่ม label ซ้ำ 2 รอบ → วัด agreement              │
└───────────────────────────────┬──────────────────────────────────────────────┘
                                ▼
┌──────────────────────────── STAGE 4 : Merge + เตรียม train set ──────────────┐
│  merge (weak ที่ G1 ปลดล็อก + LLM) → ตั้งเป้า ~10-20k                        │
│  • จัด imbalance: class weight / balanced sampler                            │
│  • split stratified ตาม label                                                 │
│  • ⚠ test ต้องเป็นชุดมนุษย์ label จริง ~1-2k (อย่าข้าม)                        │
└───────────────────────────────┬──────────────────────────────────────────────┘
                                ▼
┌──────────────────────────── STAGE 5 : Fine-tune ─────────────────────────────┐
│  PhayaThaiBERT · CE + class weight · lr ~1e-5–3e-5 · ไม่กี่ epoch              │
│                                                                              │
│  G3 ■ A/B test: เทรน "มี weak label" vs "ไม่มี" → เทียบ macro-F1 บนชุดมนุษย์     │
│      └─► weak label ช่วยจริง → เก็บ · ถ่วง → ดรอป เหลือ routing-only           │
└───────────────────────────────┬──────────────────────────────────────────────┘
                                ▼
┌──────────────────────────── STAGE 6 : Confidence + Eval ─────────────────────┐
│  softmax → temperature scaling → threshold (เช่น 0.6)                         │
│  G4 ■ จูน threshold บน val → ต่ำกว่านั้นขึ้น label "low confidence" ให้คนตรวจ   │
│  eval: macro-F1 + per-class recall + confusion matrix (ดูคลาสชนกัน)          │
└───────────────────────────────┬──────────────────────────────────────────────┘
                                ▼
┌──────────────────────────── STAGE 7 : Deploy ────────────────────────────────┐
│  export ONNX / TorchScript + quantization → inference local                  │
│  output: หมวด + confidence → เอาไปแสดงผล                                     │
└──────────────────────────────────────────────────────────────────────────────┘
```

## Key Assumptions to Validate

- [ ] **error 15-20% ของ tag rule วัดเทียบกับอะไร** (LLM? มนุษย์?) — ถ้าเทียบกับ LLM ซึ่งเองก็มี noise ~5-10% ตัวเลขจริงอาจต่างเล็กน้อย
- [ ] **error เป็นแบบ random หรือ systematic ต่อ tag** — ถ้า tag ใดแม่งๆ (เช่น tag หนึ่งผิด 50%) ต้องดรอปมันออก ไม่ใช่ยอมรับเฉลี่ย 15-20% (ทดสอบด้วย per-tag precision breakdown)
- [ ] **error ไม่กระจุกที่คลาสหายาก** — ถ้ากระจุกที่คลาสที่มีข้อมูลน้อยอยู่แล้ว จะอันตรายสุด เพราะไม่มี signal ดีๆ มาถ่วง
- [ ] **LLM label ดีพอเป็น referee** — LLM noise ~5-10% น้อยกว่า rule มาก พอใช้เป็นไม้บรรทัดได้ แต่ควรรู้ว่า noise เท่าไหร่ (G2)
- [ ] **weak label ช่วยจริง** — พิสูจน์ด้วย A/B (G3) ไม่งั้นเดา

## MVP Scope

เวอร์ชันที่ทดสอบสมมติฐานหลักก่อนขยาย:
- ใช้ weak label เป็น **routing-only** ก่อน (ปลอดภัยสุด ไม่ต้องเชื่อ rule เลย)
- LLM label ~10-20k + ชุดมนุษย์ label ~1-2k สำหรับ eval
- เทรน PhayaThaiBERT 1 ตัว baseline (LLM label อย่างเดียว)
- ทำ per-tag precision breakdown จากชุด LLM → ดูว่า tag ไหนแม่นพอจะปลดล็อก
- A/B test: เทรนเพิ่ม 1 ตัว (มี weak label ปลดล็อกแล้ว) เทียบ macro-F1

## Not Doing (และทำไม)

- **ไม่ใช้ weak label เป็น label ฝึกโดยไม่ gate** — error 15-20% แบบ systematic จะสอนเส้นแบ่งที่ผิดอย่างมั่นใจ (อันตรายสุด)
- **ไม่สร้างชุด ground truth แยกเพื่อวัด rule** — ใช้ LLM label ที่จะสร้างอยู่แล้วเป็น referee ฟรีๆ
- **ไม่แก้/ปรับ rule เอง** — เป็นระบบนอกเครื่อง ปรับยาก ใช้วิธี "เลือกเชื่อเฉพาะส่วนที่แม่น" แทน
- **ไม่พึ่ง self-training / continue MLM ตั้งแต่แรก** — WangchanBERTa/PhayaThaiBERT เห็นโซเชียลไทยมาแล้ว (wisesight ~51GB) gain น้อย เก็บเป็น option ทีหลังถ้าผลไม่ดีพอ
- **ไม่ใช้ confidence score ของ rule เป็น gate** — rule "มั่นใจแล้วตอบผิด" → คะแนนไม่ได้แยกถูก/ผิด (push back จากรอบ ideation)
